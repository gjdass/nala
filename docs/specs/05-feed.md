# 05 — Feed

Status: done

Layout vocabulary (section card, kind picker, entry sheet, mini-bar…) is defined in [04 — App layout](04-app-layout.md).

## Goal

Log every feeding of the selected baby — breastfeed, bottle (breast milk or formula) and solids — in a few taps, one-handed, and see at a glance when the last feed was and which breast to start next.

## Decisions

- **Breastfeed has two independent per-side timers (left / right).** This is a hard requirement. The Breastfeed sheet shows two side-by-side timers, each with its own duration and its own Start/Stop button. A single timer with a "side" field is not acceptable.
- **One side runs at a time.** Starting a side stops the other. Each side accumulates its own duration, and a feed can switch sides any number of times (L → R → L).
- **Live or not (spec 04 Timers).** A breastfeed is **live** while one of its sides runs, and an ordinary feed otherwise: there is no paused or finished state. Stop makes it an ordinary feed; Start on it (from its sheet) makes it live again. Save saves the start time and notes (or typed durations) and never starts or stops a side. In API names, "in progress" (`inProgress`, `breastfeedInProgress`) means live; the names are kept so requests already queued on devices still work.
- **Timers live on the server.** A live breastfeed is visible on every member's device, and anyone can switch or stop its sides. It survives closing the app. Offline, the timer runs locally and syncs later (see Offline).
- **No reminders or notifications**, ever.
- **No photos** on entries, ever.
- **Feed endpoints:** `POST /api/feeds` with `{ id, babyId, kind, startTime, notes, …kind fields }` (bottle: `milkType` `breastMilk`/`formula`, `amountMl`; solids: `mealType` `breakfast`/`lunch`/`dinner`/`snack` or null, `food`, `reaction` `liked`/`neutral`/`disliked`/`allergicReaction` or null; the fields of the other kinds are ignored and returned null) → 201 with the feed; the id is generated by the client, and sending an existing id again answers 200 with the stored feed unchanged (idempotent re-send). `PUT /api/feeds/{id}` replaces every field of the feed's kind (the baby and the kind never change) → 200; `DELETE /api/feeds/{id}` → 204; `GET /api/feeds/{id}` → 200 with the feed; unknown feed → 404 `{ code: "feedNotFound" }`. `GET /api/babies/{babyId}/feeds?cursor=&limit=` → `{ entries, next }`, newest first (start time, then id), 20 per page by default, 1–50; the cursor is opaque, a malformed one → 400 `cursor: invalid`. `GET /api/babies/{babyId}/feeds/bottle-defaults` → `{ milkType, lastAmountMl: { breastMilk, formula } }` (latest bottle's milk type, last amount of each; null when none). Unknown baby → 404 `{ code: "babyNotFound" }`. Validation problem codes: `kind` `required`/`invalid`, `startTime` `required`/`inFuture`, `milkType` `required`/`invalid`, `amountMl` `required`/`invalid` (not whole)/`outOfRange`, `mealType` `invalid`, `food` `required` (blank)/`tooLong` (over 500 once trimmed), `reaction` `invalid`, `notes` `tooLong`, `id`/`babyId` `required`. Each feed carries `loggedBy` and `updatedBy` (`{ id, displayName }`).
- **Breastfeed endpoints:** a breastfeed is driven by its timers, or entered by hand with `durations: { leftSeconds, rightSeconds, endedOn }` (whole seconds, 0–14400 = 4 h per side): `POST /api/feeds` with `kind: breastfeed` needs `durations` and creates a saved feed; `PUT /api/feeds/{id}` on a breastfeed takes optional `durations`, which replace its segments and save it (also an in-progress one). Typed durations are stored as synthetic segments running back to back from the start time, the ended-on side last (zero sides skipped); the end time is start + total. Codes: `durations` `required` (breastfeed POST without) / `outOfRange` / `zero` / `inFuture` (end more than 1 min ahead), `endedOn` `required`/`invalid` (only when both sides are above 0; otherwise the non-zero side is used). Every timer action carries client ids and the client's time `at`, so a queued one can be replayed. `POST /api/feeds/{id}/breastfeed/start` `{ babyId, segmentId, side, at }` starts `left`/`right` at `at` and stops the other side: an unknown id creates the live breastfeed (start time = `at`) → 201; an existing one becomes live again (end time cleared) → 200; re-sending a `segmentId` or starting the side that already runs changes nothing → 200. Making a feed live while another breastfeed of the baby is live → 409 `{ code: "breastfeedInProgress" }` (the sheet then opens that one), unless the body has `queued: true` (sent from a device's offline queue): the feed is then made live anyway, so a breastfeed logged offline is kept as a separate feed. `POST /api/feeds/{id}/breastfeed/stop` `{ at }` stops the running side and sets the end time to `at` (nothing running → 200 unchanged). There is no finish endpoint. `PUT /api/feeds/{id}` on a breastfeed changes its start time and notes, live or not, and leaves its sides as they are (without `durations`). The end time is the end of the last segment, null while live. `GET /api/babies/{babyId}/feeds/breastfeed` → `{ inProgress: feed | null, lastSide: "left" | "right" | null }`: the live breastfeed (with two live, the oldest), and the side of the last segment of the latest breastfeed that isn't live. Every feed carries `segments: [{ id, side, startedAt, endedAt }]` (empty for other kinds); clients derive the durations from them. Codes: `side` `required`/`invalid`, `at` `required`/`inFuture`/`invalid` (before the feed's latest segment time), `durations` `zero` (both sides at 0 s), `startTime` `afterEnd` (the end can't be before the start), `segmentId` `required`. A live breastfeed is listed in the feeds (history, card list) like any other, from its first Start. Non-breastfeed id → 404 `feedNotFound`.
- **One live breastfeed per baby** is enforced by the service, not by a unique index, so a queued offline breastfeed can be kept as a separate feed. At most one open segment per feed is enforced by the database. When a queued one makes two live, the card, the timer button and the breastfeed state show the oldest; the mini-bar lists both, each opening its own sheet.
- **Save and × in the Breastfeed sheet (spec 04 Timers).** Save: a live or stopped feed gets its start time and notes (`PUT`), and its typed durations when there are some; a feed that doesn't exist yet (typed durations only) is created (`POST`). × on a sheet opened to add, once a Start created the feed: asks to discard, then deletes it (`DELETE`, queued offline like any delete). × on an existing feed discards the form and typed durations only.
- **Existing data:** a migration sets the end time of every breastfeed without an end time and without a running segment (paused before this change) to the end of its last segment (its start time when it has none). Finish taps still waiting in a device's queue from before the change are sent as a Stop at the same time, followed by the start time and notes as an edit.
- **Manual mode in the sheet:** typing a duration with a side's pencil freezes both durations (the other side keeps its current value) and disables Start/Stop until Save or ×. Save replaces the timed segments with the typed durations, so the feed is no longer live (an explicit correction). × discards the typed durations; a running timer keeps running on the server. The "Ended on" choice (Left/Right segmented button, default: the last side typed) shows only when both sides are above 0.
- **"Still feeding?"** shows when a live breastfeed started more than 3 hours ago: a shared banner on the card (with Review, which opens the sheet) and at the top of the sheet (correct with the pencils, then Save).
- **Live sync: polling.** Live breastfeeds come from the shared live sync of spec 04 (`GET /api/live`, its `feeds` list: every baby's live breastfeed, oldest start first; 5 s while a timer runs, 30 s otherwise; paused while hidden). Its own actions apply at once. Durations tick locally from the stored timestamps, so every device shows the same live timer and any member can switch or stop it.
- **While live:** the card keeps its normal highlight ("Last feeding", the live feed being the latest) and has no timer (spec 04); + is the timer button, which opens the Breastfeed sheet. The mini-bar row reads "Feeding · L" with the running side's live duration. Once stopped, the feed leaves the mini-bar.
- **Changed or deleted elsewhere:** an open Breastfeed sheet follows side switches and stops from other devices; when its feed leaves the live list, the sheet fetches it (`GET /api/feeds/{id}`): stopped, it shows it; deleted (404), it closes with a snackbar (unless durations are being typed).
- **Offline queue (entries):** a shared device queue (`core/offline/`, `localStorage`) keeps every add / edit / delete made while the server can't be reached (no network, or 502/503/504), with the signed-in user and the time of the action. Once one waits, the user's next changes queue behind it so they arrive in order. A snackbar says "Saved on this device. It will be sent when you're back online."; the card and history stay as they were until the queue is sent, then reload (reading history needs the network). The queue is sent oldest first, one at a time, as its own user only: at app start / login, back online, when the app is shown, and every 30 s while some wait; one tab at a time (Web Locks). A network failure, a server error or 401 stops and keeps the rest; a request refused for good (other 4xx) is dropped with a snackbar "A change made offline couldn't be applied."; a queued delete answered 404 counts as done. Logout and session expiry keep the queue on the device; another user's queued changes are never sent. `createdAt` / `updatedAt` are the server's arrival times.
- **Offline timers:** timer taps (Start, Stop) go through the same device queue, each with its client ids and time; a queued Start carries `queued: true`; Save and × (delete) are queued like any edit or delete. Only the first tap kept while nothing waits shows the "Saved on this device" snackbar (Save always does). The live breastfeeds shown by the card, the sheet and the mini-bar are the server's with the waiting taps applied on top, following the server's rules (a tap already applied changes nothing). So a breastfeed started offline runs, ticks and can be switched, stopped or saved offline, and still shows after the app is reopened (the queue is on the device). Once the queue has been sent, the live list is polled at once.
- **Who logged it:** the entry sheet shows, in edit mode, "Logged by Anna · Edited by Ben, 2:40 PM" (the edited part once the feed was changed after it was logged). List items don't show it.

## User stories

- As a parent, I want to tap Start Left or Start Right to time that breast, and the other side to switch, so I don't have to do any math.
- As my partner, I want to see on my phone that a feed is live, and be able to stop it.
- As a parent, I want to add a note to the live feed without stopping its timer.
- As a parent, I want to see how long ago the last feed was and which side it ended on, so I know which breast to offer next.
- As a parent, I want to log a bottle (breast milk or formula) with how many ml were drunk, reusing the last amount in one tap.
- As a parent, I want to log solids: which meal, what the baby ate and how they reacted.
- As a parent, I want to add a feed I forgot to log, and fix or delete a wrong one.

## Acceptance criteria

Each item becomes at least one test, written failing first.

### Feed card
- [x] Highlight: "Last feeding" with the time since the **start** of the most recent feed of any kind (e.g. "26m ago"), and on the right, in an M3 display/headline typescale, the side the most recent breastfeed that isn't live ended on, capitalised ("Right" / "Left"), labelled "last side".
- [x] If there has been no breastfeed yet, the "last side" part is hidden; with no feed at all, an empty state is shown.
- [x] While a breastfeed is live, the card keeps its normal highlight and shows no timer or Start / Stop; the timer button opens the Breastfeed sheet. *(Changed by 04 slice 11; it replaced the card's running state.)*

### Breastfeed sheet
- [x] Two timers side by side, Left and Right. Each shows its side's accumulated duration and a Start/Stop button ("Start Left", "Start Right" / "Stop"; M3 tonal button, filled while that side runs).
- [x] The side the previous breastfeed ended on is marked with a "last side" label above its timer.
- [x] Tapping Start on a side when no feed is live creates a live breastfeed for the selected baby, with its start time = now, and starts that side.
- [x] Tapping Start on the other side while one side runs stops the running side and starts the tapped side.
- [x] Tapping Stop on the running side stops it; the feed is no longer live (an ordinary feed, end time = now). Start on it again makes it live again.
- [x] Each side's duration is the sum of all of its timed segments; the two durations are never merged into one stored value.
- [x] Rows: Start time (set automatically when a timer starts, editable), Total time (sum of both sides, read-only), Notes.
- [x] × on a sheet opened to add, once Start created the feed, asks to discard and then deletes the feed.
- [x] × on an existing feed discards the start time, notes and typed durations, and leaves a running side running.
- [x] Save saves the start time and notes (and typed durations) and never starts or stops a side: a live feed stays live.
- [x] Delete (shown for a live or saved feed) deletes it after confirmation.
- [x] A feed saved with both sides at 0 s is refused (Save disabled).
- [x] There is at most one live breastfeed per baby. Opening Breastfeed while one is live (e.g. started from another device) opens that feed; with none live (even a feed stopped a minute ago), a new one.
- [x] A live feed older than 3 hours shows a "Still feeding?" warning in the card and sheet, offering to save it and correct durations.

### Manual entry and correction (breastfeed)
- [x] Each side's duration has a pencil action that lets the user type a duration (minutes and seconds) instead of using the timer.
- [x] A past feed can be logged entirely by hand: set the start time, enter one or both durations with the pencils, save.
- [x] When durations are entered by hand, the user chooses which side the feed ended on (default: the side with the last edit).

### Shared timer state
- [x] The live feed, its segments and the running side are stored on the server; reloading the app or opening it on another member's device shows the same state and durations.
- [x] Other devices see changes (side switch, stop, save) within a few seconds without a manual refresh.
- [x] Durations shown are computed from stored segment start/end timestamps, not from a client-side counter, so they stay correct after the app was closed.
- [x] While a breastfeed is live, it appears in the running timers mini-bar ("Feeding · L 12m 4s", spec 04 duration format); a stopped one doesn't.
- [x] A live breastfeed is listed in the card and history from its first Start, with its live total.
- [x] Breastfeeds paused before this change get an end time from their last segment (migration).

### Bottle Feed sheet
- [x] Rows: Start time (default now), Milk type (breast milk / formula, required, segmented button), Amount in ml (required, whole number, 1–500), Notes.
- [x] The milk type defaults to the one used in that baby's previous bottle.
- [x] When the amount is empty and a previous bottle of the selected milk type exists, a suggestion row offers "Use last <milk type> amount: <n> ml?"; tapping Yes fills the amount.

### Solids sheet
- [x] Meal type at the top as single-select filter chips: Breakfast, Lunch, Dinner, Snack (optional).
- [x] Rows: Start time (default now), Food (required free text, 1–500 characters, multi-line), Reaction (optional, single-select filter chips: liked / neutral / disliked / allergic reaction), Notes.

### Entry list items
- [x] Breastfeed: `breastfeeding` icon, time, then "Total 8m 30s · L 5m · R 3m 30s" (an unused side left out). No duration bar.
- [x] Bottle: bottle icon, time, "<milk type> · <n> ml".
- [x] Solids: `nutrition` icon, then a headline with the time, the meal type and the reaction when there are any ("12:00 PM · Lunch · Liked"), then the food text on one line (ellipsis when too long), so the row has the same height as the others.
- [x] Entries logged by a deleted account still show that person's display name.

### Editing and validation
- [x] Any member can edit or delete any feed; changes are saved with who edited it and when.
- [x] Times cannot be in the future (1 minute tolerance), and a breastfeed's end cannot be before its start.

### Offline
- [x] With no network, every action above that creates or changes a feed (timer taps, save, manual entry, edit, delete) is queued on the device with its own timestamp and applied when back online.
- [x] While offline, a breastfeed timer started on this device keeps running and displaying correctly.
- [x] Re-sending a queued action is idempotent (client-generated UUIDs for feeds and segments).
- [x] If the session has expired while entries are queued offline, the queue is kept on the device; it is sent after the user logs in again, as the same user only (moved from 02).
- [x] If a queued breastfeed reaches the server while another feed is live for the same baby, both are kept as separate feeds; nothing is dropped.

## Data

A feed is one entity with a kind (breastfeed / bottle / solids) and kind-specific fields; breastfeed timing is stored as segments.

- **Feed:** id (client UUID), baby, kind, start time (UTC), end time (UTC, breastfeed only: end of the last segment, null while live), notes, logged by user, created at, updated at, updated by user.
  - Bottle: milk type (breast milk / formula), amount ml.
  - Solids: meal type (nullable), food, reaction (nullable).
- **BreastFeedSegment:** id (client UUID), feed, side (left / right), started at (UTC), ended at (UTC, null while running). At most one open segment per feed.
- Derived, not stored: per-side duration (sum of segments), ended-on side (side of the last segment), running side, live (a segment is open).
- A breastfeed with durations typed by hand is stored as synthetic segments: one per side with a non-zero duration, ordered so the ended-on side comes last.
- Feeds are deleted with their baby (03).

## UI notes

- Section colour token: `feed` (light and dark values in the global theme).
- New shared components for this feature: **split timer** (two side-by-side timers with Start/Stop and a pencil for manual duration) — reused later by Pump; **duration field** + **duration dialog** (minutes and seconds, 4 h at most) behind the pencils; **banner** (`nala-banner`, e.g. "Still feeding?", shown on the card through the section card's `[sectionBanner]` slot).
- Live updates across devices: server-sent events or polling; the choice is technical, the requirement is "within a few seconds".
- All text through i18n (EN/FR).

## Out of scope

- Reminders and notifications (never).
- Photos (never).
- Daily totals, statistics and charts.
- Combined breastfeed + bottle top-up as a single entry (log them as two feeds).
- A food catalogue or per-food allergy tracking beyond the reaction field.
- Pumping (feature 08).
